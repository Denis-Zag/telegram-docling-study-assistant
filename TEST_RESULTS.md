# Результаты проверки Telegram Docling Study Assistant

Дата проверки: 8 октября 2026 года.

## Офлайн-проверки

Я выполнил следующие проверки:

- `pytest`: 12 тестов пройдено;
- `Ruff`: замечаний нет;
- `compileall`: синтаксических ошибок нет;
- `pip check`: конфликтов установленных зависимостей нет.

Тесты проверяют:

- стабильные и изолированные пользовательские namespace;
- метаданные имени файла, чанка, страницы и заголовка;
- документы без заголовков и provenance;
- запрет неподдерживаемых форматов;
- резюме в одном предложении;
- правила ответа только по найденным материалам;
- удаление повторяющихся источников;
- обработчики загрузки документа и текстового вопроса в Telegram.

## Демонстрационный документ

Я подготовил трёхстраничный PDF с техническим описанием собственного проекта
Auto Service AI Triage. 
Текст извлекается со всех трёх страниц.

## Живая проверка

Я запустил полный `preflight.py` на демонстрационном PDF с контрольным вопросом
про разделение памяти разных клиентов и диалогов.

```powershell
python preflight.py .\output\pdf\Auto_Service_AI_Triage_Overview.pdf --question "Как система разделяет память разных клиентов и диалогов?"
```

Фактический результат:

```text
Telegram: OK
Docling + ProxyAPI embeddings + Pinecone: OK (14 чанков)
ProxyAPI summary: OK
Haystack generation pipeline: OK
Источник: Auto_Service_AI_Triage_Overview.pdf, стр. 2
Pinecone: тестовый namespace очищен
Preflight завершён. Telegram polling не запускался.
```

В сформированном ответе указано, что память разделяется по сочетанию `client_id`
и `thread_id`, а checkpoint ID создаётся как SHA-256 от этих двух значений. Это
соответствует фактам на второй странице PDF. Проверка подтвердила живые обращения
к Telegram, ProxyAPI и Pinecone, а не только работу офлайн-тестов.

## Ручная проверка в Telegram

После загрузки тестового PDF я задал боту два вопроса по документу, один вопрос не по теме
и запросил состояние базы знаний.

### Вопрос о разделении памяти

На вопрос «Как система разделяет память разных клиентов и диалогов?» бот корректно объяснил
разделение по сочетанию `client_id` и `thread_id`, создание checkpoint ID и изоляцию диалогов.
В ответе указан один источник:

```text
Auto_Service_AI_Triage_Overview.pdf, стр. 2
```

### Вопрос о сведениях для заявки

На вопрос «Какие сведения агент должен собрать до отправки заявки и какие сведения являются
необязательными?» бот перечислил обязательные данные: автомобиль, описание проблемы, время и
обстоятельства её появления. Дополнительные сведения он отнёс к необязательным. В ответе указан
один источник:

```text
Auto_Service_AI_Triage_Overview.pdf, стр. 3
```

### Вопрос не по теме документа

На вопрос «Сколько стоит букет цветов?» бот не стал придумывать цену и ответил:

```text
В загруженных материалах нет достаточной информации.
```

Эта проверка показала, что бот ограничивает ответ содержимым загруженных материалов.

### Состояние базы знаний

Команда `/document_status` подтвердила количество сохранённых фрагментов:

```text
В вашей базе знаний фрагментов: 14.
```

## Повторная проверка поиска

Во время ручного диалога один запрос завершился временным таймаутом Pinecone, а
для другого вопроса нужный фрагмент находился ниже первых пяти результатов. Я
добавил один повтор поиска только при таймауте Pinecone и увеличил
`DOCUMENT_TOP_K` с `5` до `8`.

После исправления я повторил оба вопроса. Бот корректно объяснил изоляцию памяти
через `client_id`, `thread_id` и SHA-256, а также перечислил обязательные и
необязательные сведения для заявки. Обновлённый набор из 12 офлайн-тестов и Ruff
прошли без ошибок.

## Проверка точности источников

Сначала бот показывал страницы всех восьми найденных фрагментов, даже если для
ответа требовалась только одна страница. Я пронумеровал передаваемые модели
фрагменты метками `S1`-`S8` и потребовал вернуть минимальный набор использованных
меток в отдельной служебной строке. Перед отправкой сообщения бот удаляет эту
строку и преобразует выбранные метки в обычный список источников.

В повторной живой проверке вопрос о разделении памяти сослался только на страницу
2, а вопрос об обязательных и необязательных сведениях - только на страницу 3.
Служебные метки в пользовательских ответах не отображаются.

## Итог

Я подтвердил, что бот преобразует PDF в персональную базу знаний, отвечает по найденному контексту,
показывает точные страницы источника и не выдумывает ответ, если в документе нет нужных сведений.
В тестовой базе знаний сохранено 14 фрагментов. Два контрольных ответа сослались только на страницы 2 и 3,
где находятся нужные факты.
